I plan the project, choose the right level of technology — from a single fast HTML file to a full-stack platform — and build it with AI-assisted tools organized into a personal workflow.

I am an undergraduate at the Faculty of Economics and Political Science, Cairo University (expected graduation 2027), working independently from Shebin El-Kom.

I keep my claims honest: every skill below is backed by a project you can open, and concept demos are labeled as concepts. What I can show is careful process — audits, plans, tests, and iterations.

How I Build

With real examples from my projects

  1. Understand the problem

    For Al-Diwan I wrote a deep audit first — it showed orders lived only in the browser and had no backend. That finding shaped everything after.

  2. Research

    I keep research notes before building: the Rollz project has a location review and a 50-item development-ideas document; my template library holds 53 researched templates with verification logs.

  3. Plan

    The Al-Diwan backend had a written implementation plan: keep the storefront, add an API, migrate nothing destructively, test each step.

  4. Choose the right level of technology

    A single fast HTML file when that's enough (client sites); Next.js + Supabase when a store needs accounts and orders (SHE); a Workers API when orders must be trusted (Al-Diwan).

  5. Build

    Ship small, keep versions: my portfolio alone went through ten-plus named iterations, and each client site reuses a tested core.

  6. Test & audit

    I write and run real tests: 33 integration assertions and a 10-step end-to-end order journey for the Al-Diwan API — with an honest list of what was not tested.

  7. Review & improve

    Client sites ship with before/after comparisons, and every project ends with a written readiness report and a to-do list for the next version.

كيف أعمل

بأمثلة حقيقية من مشاريعي

  1. أفهم المشكلة

    للديوان كتبت تدقيقًا عميقًا أولًا — بيّن أن الطلبات كانت تعيش في المتصفح فقط بلا خلفية. تلك النتيجة شكّلت كل ما بعدها.

  2. أبحث

    أحتفظ بملاحظات بحث قبل البناء: مشروع Rollz فيه مراجعة للموقع ووثيقة أفكار تطوير من 50 بندًا؛ ومكتبة قوالبي تضم 53 قالبًا مدروسًا بسجلات تحقق.

  3. أخطّط

    خلفية الديوان كان لها خطة تنفيذ مكتوبة: إبقاء الواجهة، إضافة API، بلا ترحيلات مدمّرة، واختبار كل خطوة.

  4. أختار المستوى المناسب من التقنية

    ملف HTML سريع واحد حين يكفي (مواقع العملاء)؛ Next.js + Supabase حين يحتاج المتجر حسابات وطلبات (SHE)؛ وAPI على Workers حين يجب أن تكون الطلبات موثوقة (الديوان).

  5. أبني
